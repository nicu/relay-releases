The Assistant

The Assistant is a chat beside your issues. It reads the issue, its comments and fields, its epic, and the code written for it in your repositories, and then answers a question or writes a draft: a comment, a description, testing instructions, release notes. You read the draft, change it if you like, and post it. Nothing reaches Jira until you press Post.

It's optional. Until you choose a model, Relay doesn't show the Assistant at all, and everything else works the same.

Choosing a model​

Open Settings › Model and pick a Provider:

  • OpenAI-compatible: any server with an OpenAI-compatible API, such as LM Studio, Ollama or llama.cpp on your computer, or a server elsewhere. Enter its Endpoint (usually ending in /v1), press Test, and pick the Model from the list.
  • Claude: Anthropic's API, with your API key from console.anthropic.com.
  • OpenAI: OpenAI's API (GPT and Codex models), with your API key from platform.openai.com.

API keys are kept in your system's keychain and never shown again. A key for a server you run yourself is only sent over https, or to this computer.

For a local model, use one that supports tool calls and has a context of 32k tokens or more: smaller models often ignore the tools, and a short context cuts long changes without saying so.

What leaves this computer says where your data goes with the settings you chose. With a server on your computer: nothing. With Claude, OpenAI or a remote server: the issue you ask about and excerpts of its code go to them when you run the Assistant.

Speed › Answer times shows how long the model took lately, once it has answered a few times, so you can compare models or settings.

Linking your code​

In Settings › Repositories, Add a repository… and pick the folder of a local clone. The Assistant reads it and never changes it. With repositories linked, it finds the code for an issue by its key:

  • a branch whose name holds the key (feature/NW-118-price-list-errors), compared with your main branch;
  • otherwise, commits whose message mentions the key.

It can then read more with its own read-only tools: list and read files, search, outline a file's functions, and look at commits and diffs.

It never reads secrets or what you keep out of git: .env files, keys and certificates, credential files, anything under .ssh or .aws, files git ignores, binary files and very large ones. Nothing in a repository can make it run a program.

With several repositories linked, it reads the ones whose branches or commits name the issue, and asks you which when it can't tell. Settings › Assistant › Use code from repositories turns code reading off altogether; answers then come from Jira only.

Asking about an issue​

Open an issue and press ⌘J (Ctrl+J on Windows and Linux), or pick Assistant at the top of the side panel. A new chat offers your quick actions, the recipes you use most, as cards.

Type a question and press ⌘↵. While it works you see each step (reading the branch, searching the code) and the answer as it's written; Esc stops it. Under the answer, a line says what it was based on: the branch, commits, files and comments it read. Open tool calls to see each one, what it was asked and what came back.

Follow-up questions keep the conversation: the Assistant remembers what was said. In the box, / lists recipes, @ mentions a person and # brings in another issue.

Drafts: nothing is posted until you say so​

When you ask for something to post, such as a reply or release notes, the answer is a draft, with its buttons under it:

  • Post as comment (or Save as description, or Save to a field): sends it to Jira, like a comment you wrote, with undo.
  • Edit: change the text first, then post.
  • Copy, Regenerate (a new attempt) and Discard.

Once posted, the chat says so, and the comment is on the issue. ⌘Z takes it back.

A draft for the description or a field (Testing instructions, for example) waits in that field on the issue, marked Suggested by Assistant, with Accept, Edit first and Discard.

The keys work on the draft shown: ⇧⌘↵ posts it, ⇧⌘E edits it, ⇧⌘⌫ discards it, and ⌥⌘R writes it again.

The Assistant page​

⌘6 opens the Assistant page: every chat in History, grouped by Issues, Epics, General, Rules and Scheduled, the open chat in the middle, and its Context on the right (the issue, its fields, and the branch and commits the chat used). ⇧⌘A moves a chat from beside an issue to this page, and back. ⇧⌘\ hides the history.

⌘N starts a chat that isn't about one issue: about your work, an epic (pick it with #), or anything you ask. These chats can look things up in Relay themselves: search issues, read your worklogs and activity, see Inbox. Recipes for your work in general start here, such as Standup notes or Weekly summary; see Recipes.

What it can change​

Settings › Assistant › Assistant can decides:

  • Read (the default): it reads, and drafts. It can also make timesheet drafts, which stay in Relay until you accept them on the Timesheet.
  • Read & write: it can also change issues, comment, log work and triage Inbox when you ask it to. With Ask before changes on (the default), each change waits in Inbox for your OK.

Privacy​

  • The Assistant runs in a process of its own. Its code tools read only the repositories you linked, never change them, and leave out secret and ignored files.
  • With a model on your computer, nothing leaves it.
  • With Claude, OpenAI or a remote server, what goes to them is what the chat needs: the issue, its comments and fields, its epic, excerpts of the code it read, and, in a general chat, what Relay's own lookups return.
  • Rules can ask the Assistant for a draft, but nothing is ever posted for you: the draft waits in Inbox until you review it.

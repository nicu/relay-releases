Recipes

A recipe is a job you give the Assistant again and again: what to ask, what it reads, and where the answer goes. Testing instructions reads the issue, its comments and its code, and writes instructions a tester can follow; Standup notes reads what you did yesterday and what's in progress, and writes your standup. Relay comes with a set, and you can change them or write your own.

Recipes need the Assistant: they show once a model is set up.

The recipes Relay comes with​

On one issue:

RecipeWhat it doesResult
Description from codeWrites the issue's description from the code change: summary, changes, how to try itThe description
Release notesA release note for the people who use the product, from the issue and its changeA comment draft
Testing instructionsSteps a tester who can't read code can follow, with what to expect, edge cases and open questionsThe issue's Testing instructions field, if it has one; else a comment draft
What’s left in code?TODOs, parts of the issue the change doesn't cover yet, missing tests, whether it's mergedAn answer in the chat
What changed since last test?What happened since the issue last went to testing, and which steps to run againAn answer in the chat
Steps to reproduceNumbered steps, with the expected and the actual resultAn answer in the chat
Edge casesUp to ten unusual inputs or states to try, each with its expected resultAn answer in the chat
SummaryThe issue in a few sentences, for someone who hasn't followed itAn answer in the chat
Release note, plain languageA shorter release note, with no technical wordsA comment draft
What’s blocking it?What it waits on, since when, and who could unblock itAn answer in the chat
Ready to ship?Yes, Not yet or Unclear, with what's done and what's missingAn answer in the chat
Why is this here?Why an item is in your Inbox, and whether you need to do anythingAn answer in the chat

Recipes that need code (Description from code, What’s left in code?) are offered only while a repository is linked.

Running a recipe​

On an issue, wherever you are:

  • Its menu (right-click it, or ⇧F10): Ask the Assistant ▸ lists your quick actions, then More recipes ▸.
  • ⌘K: with an issue selected, every recipe is there as "Testing instructions for NW-118".
  • The chat: a new chat shows your quick actions as cards; in the box, / lists every recipe.

The recipe runs in the issue's chat, and its answer arrives like any other: a draft to post, or an answer to read.

Quick actions, the recipes one click away, are yours to pick: Settings › Assistant › Quick actions lists the issue recipes to tick and drag into order. In Inbox, an item's chat offers its own: Why is this here?, Summarise, Draft a reply and Was it shipped?.

Recipes about your work in general start a chat on the Assistant page (⌘6, then ⌘N): pick one of the cards, or type /.

Writing your own​

⌘5 opens the Recipes page: every recipe, filtered by All, Issue or General, in the order menus show them (drag to reorder). Pick one to change it in the editor on the right.

⌘N (or New recipe) starts one:

  • Name and Icon: how it shows in menus, ⌘K and the chat.
  • Runs on: One issue, or General (your work, an epic, a sprint; its answer is always a note in the chat).
  • Instructions: what the Assistant is asked to do, in your own words (Markdown).
  • Reads: The issue, Comments, Rich-text fields and Code. Needs code keeps it out of quick actions while no repository is linked.
  • Result: a Comment draft, the Description, one of your site's rich-text fields, or a Note in the conversation. Whatever it is, nothing reaches Jira until you post or save it.

Changes save as you type; ⌘Z steps back through them. ⌘D duplicates a recipe and ⌘⌫ deletes it.

The Recipes menu at the top of the page imports and exports recipes as files (Import…, Export ▸ All Recipes… or This Recipe…), so you can share them with your team. A recipe Relay came with that you deleted stays deleted; Restore Default Recipes brings them all back as they shipped, and Start Clean… removes them, keeping your own.

Recipes from rules​

A rule can run a recipe for you: add the Ask the Assistant action to it and pick the recipe. On a rule about changes or an issue's state, an issue recipe runs on each issue the rule matched; a general one looks at the Matched issues, My work, the Sprint or a JQL search.

With When › Every … at …, it runs on a schedule. A rule that writes your standup notes every weekday at 9:15:

When it's done, Inbox says so ("Standup notes ready", or "Release notes ready to review" for a draft), and opening the item opens the chat. The rule never posts anything: a draft waits for you there. Chats a scheduled rule starts are under Scheduled on the Assistant page. See Inbox and rules for how rules work.

Open in another AI app​

An issue, or any chat's subject, can also go to an outside AI app instead of Relay's own Assistant: Claude Code, Claude, Codex / ChatGPT or ChatGPT (web). The app opens with a short prompt already written (the issue and, if you picked one, a recipe's job), and nothing is sent until you send it there. Apps that work in a folder, Claude Code and Codex, open in the issue's repository.

  • An issue's menu: Open in ▸, then the app: the issue as it is, or with one of your recipes.
  • ⇧⌘J opens the issue in your default app, set in Settings › MCP & integrations › Open in, where you also choose whether Claude Code opens in Claude Desktop or a terminal.
  • In any Assistant chat, the ⌄ beside Ask sends what you write to an outside app instead; Ask then reads "Ask Claude Code", and recipes picked with / go there too.

The prompt stays short because the app reads the issue itself, through Relay's MCP tools. Turn on Relay's MCP server in Settings › MCP & integrations › Local MCP server, and add the app under Clients once. If an app isn't installed, Relay copies the prompt for you to paste.

The chat keeps a note of what went where, with Open again, Copy prompt and Show prompt. Open in works without a model set up.
